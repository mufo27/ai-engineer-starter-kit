## เช็กลิสต์ก่อนอัด

- [ ] `cp .env.example .env` แล้วใส่ `GEMINI_API_KEY` (หรือ OpenAI/Anthropic) เพื่อให้โหมด "live" ทำงาน
- [ ] `docker compose up -d --build` — เช็คให้ api `:8000`, web `:3000`, db, redis healthy ครบ
- [ ] รัน `make demo` 1 รอบล่วงหน้า เพื่อให้ response พร้อมและไม่มีอะไรสะดุดหน้ากล้อง
- [ ] ซูมฟอนต์ terminal/editor ให้ใหญ่ (~14px+), ปิด notification, ใช้ธีมสว่าง
- [ ] เปิดแท็บ GitHub repo ไว้ (https://github.com/mufo27/ai-engineer-starter-kit)
- [ ] อัดเป็น 16:9, 1080p, ขยับเมาส์ช้าๆ

## 0:00 – 0:15 — เปิดเรื่อง (Hook)

**บนจอ:** หน้า README ของ repo (มี badges + แผนภาพ architecture)

**บทพูด:**
> "นี่คือ AI Engineer Starter Kit — โครงสร้างพร้อมใช้ระดับ production สำหรับสร้างแอป LLM
> ไม่ใช่ของเล่นเดโมครับ มันมี router เลือกหลายผู้ให้บริการอย่างชาญฉลาด, ระบบ RAG แบบไฮบริด
> ที่อ้างอิงแหล่งที่มา, การเก็บเวอร์ชัน prompt, ชุดประเมิน (eval) ที่ใช้เป็น quality gate ใน CI,
> การติดตามต้นทุน, ระบบยืนยันตัวตนแบบ multi-tenant และ deploy ได้ด้วย Docker กับ Helm
> เดี๋ยวผมทำให้ดูว่ามันใช้งานได้จริง"

---

## 0:15 – 0:35 — ภาพรวมสถาปัตยกรรม

**บนจอ:** เลื่อนไปที่แผนภาพ Mermaid ใน README ชี้ทีละกล่องตามที่พูด

**บทพูด:**
> "รีเควสต์จะไหลผ่าน pipeline ครับ — เริ่มจากตรวจ auth และ scope, ตัวจำกัดอัตรา (rate limiter),
> โควตาต่อเดือน, และตัวคุมงบแบบ fail-closed จากนั้น LLM router จะจำแนกประเภทงานแล้วเลือกโมเดล
> ที่ถูกที่สุดที่ทำงานได้ — จะเป็น OpenAI, Anthropic, Gemini หรือเจ้าที่เข้ากันได้กับ OpenAI ก็ได้หมด
> ฝั่ง RAG จะฝัง embedding ของคำถาม ค้นหาแบบไฮบริดทั้งเวกเตอร์และคีย์เวิร์ดใน pgvector, rerank
> แล้วสร้างคำตอบที่อ้างอิงจากข้อมูลจริงพร้อม citation ทุกอย่างถูก trace และนับค่าใช้จ่าย
> หลักการเดียวที่อยู่เบื้องหลังทั้งระบบคือ fail-closed — ถ้าตอบอย่างปลอดภัยไม่ได้ มันจะปฏิเสธ
> ไม่แต่งคำตอบขึ้นมาเอง"

---

## 0:35 – 0:50 — เปิดระบบ

**บนจอ:** terminal — พิมพ์ `docker compose up -d --build` แล้ว `curl localhost:8000/health`

**บทพูด:**
> "คำสั่งเดียวเปิดทั้ง stack ครับ นี่คือ health check — API พร้อมใช้งาน
> และมันบอกด้วยว่าเปิดใช้ provider ตัวไหนบ้าง" *(โชว์ JSON: `providers_enabled: true`)*

---

## 0:50 – 1:10 — Routing + ต้นทุน

**บนจอ:** `curl` ไปที่ `/v1/chat` แล้วไฮไลต์ `provider`, `model`, `cost_usd`, `task_type` ใน response

**บทพูด:**
> "รีเควสต์ chat จะถูกจำแนกและ route อัตโนมัติ สังเกตว่า response บอกทั้งเลือก provider และโมเดลไหน
> จำนวน token และต้นทุนเป็นดอลลาร์เป๊ะๆ — นั่นคือ cost middleware ที่นับทุก call
> ถ้าใส่ API key จริง มันจะไปเรียกโมเดลจริง แต่ถ้าไม่มี key มันจะ fallback เป็น mock
> ทำให้รันได้แบบออฟไลน์ทั้งหมด"

---

## 1:10 – 1:30 — RAG พร้อม citation

**บนจอ:** `POST /v1/documents` (ingest) แล้ว `POST /v1/ask` — ไฮไลต์คำตอบ + `citations`

**บทพูด:**
> "ทีนี้มาดู RAG ครับ ผมป้อนเอกสารเข้าไป — มันจะถูกตัดเป็นชิ้น ฝัง embedding และเก็บในฐานข้อมูล
> จากนั้นผมตั้งคำถามว่า 'ร้านนี้ขายอะไรและอยู่ที่ไหน' คำตอบที่ได้จะอ้างอิงจาก chunk ที่ดึงมาจริง
> พร้อม citation ชี้ไปยังแหล่งที่มาตรงๆ และคะแนนความเกี่ยวข้อง — ไม่มีการมั่ว
> และทุกข้อความตรวจสอบย้อนกลับได้"

---

## 1:30 – 1:50 — A/B eval dashboard

**บนจอ:** เปิด dashboard `localhost:3000` → ติ๊ก "Use live provider" → Run comparison → โชว์ winner banner + KPI เทียบข้าง + ตารางรายข้อ

**บทพูด:**
> "นี่คือ A/B eval dashboard ครับ ผมเปรียบเทียบ prompt สองเวอร์ชันบนชุดทดสอบ (golden set) ได้
> ผมจะเปิดโหมด live provider เพื่อให้ใช้โมเดลจริง แล้วกดรัน — จะเห็นว่า prompt แบบสั้น
> ชนะ prompt แบบยาวในเรื่อง faithfulness ทีละข้อเลย และคะแนนชุดเดียวกันนี้ยังรันเป็น CI gate ด้วย
> ถ้าคุณภาพการค้นหาลดต่ำกว่าเกณฑ์ การ build จะ fail ทันที"

---

## 1:50 – 2:10 — Deploy + ปิดท้าย

**บนจอ:** แตะโฟลเดอร์ `k8s/helm` สั้นๆ + หน้า GitHub Actions ที่ pipeline เขียว

**บทพูด:**
> "พร้อม deploy ครับ — มี Helm chart ที่รองรับ autoscaling และ ingress, พร้อม CI pipeline
> ที่ lint, test, ประเมินคุณภาพ, build image และ deploy ขึ้น staging
> ทั้งเทสต์ ทั้ง type check ทั้ง lint ผ่านหมด เป็น open-source สัญญาอนุญาต MIT — ลิงก์อยู่ในคำอธิบาย
> ขอบคุณที่รับชมครับ"
